# WaferLog · 硅笺｜页面功能说明（MVP）

> 产品主张：**每一笔，都会回响。**  
> 核心能力：用户可以以最低门槛记录；需要回看时，过去的记录能以可溯源的方式回应当下。

## 0. 产品结构

| 页面 | 解决的问题 | 用户主动作 |
| --- | --- | --- |
| 档案馆（首页） | 今天值得回看的过去是什么？ | 进入旧笔记、打开记录库 |
| 所有记录 | 我以前写过什么？ | 搜索、筛选、打开原稿 |
| 单页详情 | 这页笔记里有什么可用信息？ | 看原稿 / OCR / 关联、提问 |
| 主题盒 | 哪些记录在长期讨论同一件事？ | 按主题聚合回看 |
| 记忆线 | 一个想法是怎样逐步形成的？ | 沿时间查看强关联笔记 |
| 时间册 | 我的记录、待办和日期如何对应？ | 展开待办、确认加入日历 |
| 知识问答 | 我过去的记录如何回答现在的问题？ | 主动提问、打开来源 |
| 设置 | 硬件、同步和体验如何配置？ | 查看同步、修改偏好 |

---

## 1. 档案馆 / 记忆显影台（首页）

### 页面定位

不是普通的“最近笔记”仪表盘，而是硅笺的独特入口：将**刚刚写下的内容**与**值得重逢的旧记录**并置。

### 核心模块

1. **刚刚落笔**
   - 用手写纸页形式展示最新一条记录。
   - 显示记录时间、输入方式（手写 / 文字 / 语音）和简短内容。
   - 点击“打开这页”进入单页详情。

2. **记忆回路**
   - 中心显示本次记录触发的回响数量。
   - 周围显示与它有关的历史笔记时间点和主题。
   - 这是“过去回应现在”的视觉表达，不做复杂全局知识图谱。

3. **回响票据**
   - 展示 1 条最强关联的旧笔记，以及 1 条次强关联。
   - 每条须说明关联原因，例如“它解释了你今天为什么想做低干扰”。
   - 用户点击后才进入旧笔记；不在书写时弹窗打断。

4. **还在生长的纸页**
   - 最近归档的笔记入口。
   - 用于用户主动进入完整记录库。

### 第一版规则

- 每次进入档案馆，至多展示一组“值得重逢”。
- 仅在关联置信度足够高时展示回响；没有强关联时应诚实显示“这页正在等待新的连接”。
- 不自动替用户做结论或主动出题。

---

## 2. 所有记录

### 页面定位

保存所有原始记录的档案入口。**原始手写页是主角**，AI 整理结果是附着层。

### 核心模块

- 笔记卡：缩略原稿、标题、日期、输入方式、主题标签、回响数量。
- 搜索：按标题、OCR 文本、主题检索。
- 筛选：全部 / 手写 / 语音 / 文字、时间范围、主题、有回响。
- 时间分组：默认按月或日期展示。

### 关键交互

- 点击任意卡片进入“单页详情”。
- 用户可手动修改 AI 自动归类的主题。
- 删除入口应轻量且明确；删除前确认，删除后进入回收站。

---

## 3. 单页详情

### 页面定位

把一页原始记录变成“可阅读、可检索、可继续思考”的材料，但不取代原稿。

### 核心模块

1. **原始页面**：手写图像或文字正文。
2. **整理信息**：标题、记录方式、日期、主题标签。
3. **OCR 标签页**：提取出的可复制文字，并可回到原稿对应区域。
4. **关联标签页**：相关旧笔记及其关联依据。
5. **待办候选**：AI 从内容识别出的行动项和可能截止时间，用户确认后才加入日历。
6. **提问入口**：将当前页作为限定范围，进入知识问答。

### 第一版规则

- AI 不能改写、覆盖或替代用户原始笔记。
- 每一个关联和问答结论都必须能打开来源页。

---

## 4. 主题盒

### 页面定位

让零散记录形成用户可理解的长期主题，而不是强迫用户每次记笔记时分类。

### 核心模块

- 主题名称、包含笔记数、简短描述、回响数量。
- 主题可由 AI 自动分类，用户可以改名、合并、移出笔记。
- 同一条笔记可以属于多个主题。

### 示例主题

产品设计、学习方法、随手灵感、知识管理、项目管理、未整理。

---

## 5. 记忆线

### 页面定位

用一条沿时间延展的线，说明某个想法如何从早期观察发展到今天；它是**叙事型关联**，不是密集的知识图谱。

### 核心模块

- 当前记录（NOW）。
- 关键历史节点（PAST）。
- 每个节点显示：日期、标题、简短原意、关联主题。
- 允许打开任一节点的原始手写页。

### 第一版规则

- 仅呈现高质量的 3–5 个强关联节点。
- 关联说明需要是人能读懂的自然语言，例如“这一页提出了今天方案的起点”。

---

## 6. 时间册（日历）

### 页面定位

把“哪天写了什么”“哪些行动要发生”放入同一时间地图；它不是单纯待办软件。

### 默认月视图

- `●`：已确认待办。
- `✦`：有回响或重要记录。
- `━`：当天有记录。
- 天气小组件：显示日期对应的本地天气信息。

### 待办交互

1. 默认不在每个日期格显示任务文字，保持月视图轻量。
2. 点击“展开待办”后，显示每日框内的待办名称。
3. AI 识别出待办和时间后，进入右侧“待确认”区域。
4. 用户可选择：`一键加入日历`、修改日期、稍后处理、忽略。

### 第一版边界

- 日程同步可先做本地 / 云端账户内同步；第三方日历接入可后置。
- 不做强提醒轰炸，提醒策略应由用户配置。

---

## 7. 知识问答

### 页面定位

一个只面向“我的档案”的主动提问工具，不是通用聊天机器人。

### 核心模块

- 问题输入框。
- 检索范围选择：全部档案 / 某主题 / 某一页记录。
- 回答内容：基于记录整理出的观点、脉络或对比。
- 来源卡：显示引用的手写页、日期、原稿区域；点击可以回到来源。

### 示例问题

- “我以前为什么认为低干扰输入重要？”
- “和产品设计有关的想法有哪些还没有变成行动？”
- “我在这个项目上反复提到的担忧是什么？”

### 第一版规则

- 只做用户主动提问。
- 回答没有足够来源时，要明确说“档案中没有足够依据”，不编造。
- 不做主动出题、自动复习计划或泛化闲聊。

---

## 8. 设置

### 核心模块

- T5 设备连接状态、Wi‑Fi、同步状态。
- 云端同步与存储空间。
- 默认纸张、语音输入开关、天气位置。
- 外观主题、语言、回收站和数据导出。

---

## 9. T5 端与 Web 端分工

| 场景 | T5 设备端 | Web 端 |
| --- | --- | --- |
| 记录 | 开机即空白纸，手写 / 语音 / 文字，自动保存 | 查看、编辑文本、补充整理 |
| 原稿 | 本地保留手写内容与缩略图 | 高清浏览、OCR 阅读、搜索 |
| AI 关联 | 仅显示轻量回响提示，不打断书写 | 展示关联依据、记忆线、知识问答 |
| 待办 / 日历 | 快速确认与查看当天 | 月视图管理、修改时间、筛选 |

---

## 10. 团队开发优先级

### P0：Demo 必须跑通

1. 手写记录创建与自动保存。
2. 原稿上传 / 云端同步。
3. 记录库浏览与单页详情。
4. OCR 文本展示。
5. 单条“回响”关联及来源跳转。
6. 用户主动问答，答案附来源。
7. 待办候选确认后加入日历。

### P1：体验增强

- 主题自动分类与人工修改。
- 记忆线生成。
- 语音转文字。
- 日历展开待办与天气。

### 暂不做

- 主动出题、强制复习。
- 复杂全局知识图谱。
- 会议录音 / 转写硬件模块。
- NFC 投屏等扩展硬件能力。

## 11. 一句话演示路径

用户在 T5 上随手写下一页草图 → 自动保存并同步 → Web 档案馆显示一条与旧笔记的回响 → 用户打开来源，理解这条思考线 → 在知识问答中追问 → 从笔记识别出的待办由用户确认后进入时间册。
