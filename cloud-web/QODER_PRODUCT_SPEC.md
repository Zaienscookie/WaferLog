# WaferLog · 硅笺｜产品功能说明（交给 Qoder）

## 使用方式

这是 **功能与产品约束文档**，不包含页面布局、配色、字体、组件形态或任何既有 UI 方案。

请将本文件交给 Qoder 的产品、架构、前端、后端和测试 Agent。它们可以自由重新设计界面，只需满足本文件定义的产品目标、用户流程和验收条件。

---

## 1. 产品是什么

硅笺是一个会帮你"想起以前"的手写笔记本。灵感、待办、涂鸦，随手记进去就行，不用分类，不用整理。某天你打开它，那些差点忘掉的旧想法已经在那里等你了——**随手一笔，久久有回响。**

产品名：**WaferLog · 硅笺**
Slogan：**随手一笔，久久有回响。**

## 2. 目标用户与真实痛点

- 用户：学生、独立创作者、知识工作者、经常用手写记笔记的人。
- 痛点：灵感很容易记下，却很难在需要时找回；用户不愿在记录当下先分类、建文件夹、做整理。
- 要解决的问题：让"记录"足够轻，让"回看、关联、行动"在之后自然发生。

## 3. 不可改变的产品原则

1. **先记录，后整理**：用户创建记录时不需要先选主题或文件夹。
2. **原稿优先**：手写内容 / 原始文本是第一层信息，AI 只能帮助阅读、检索和关联，不能覆盖原稿。
3. **AI 不打断书写**：不在用户写作过程中弹总结、建议或推荐。
4. **用户主动触发 AI**：第一版仅做用户主动提问；不做主动出题、强制复习、泛聊天。
5. **所有 AI 结论可溯源**：关联和回答必须能回到具体原始记录。
6. **用户确认后才行动**：识别到待办 / 日期时，系统只能给出候选，用户确认后才能加入日历。

## 4. 必须跑通的主流程

```text
新建记录（手写或文字）
  → 自动保存原始内容
  → 得到可检索文本（OCR 或用户提供的文字）
  → 系统找到一条或多条旧记录关联
  → 用户查看关联来源 / 主动提问
  → 回答展示引用的来源记录
  → 从记录中确认一项待办并加入日历
```

## 5. 功能范围与验收条件

| 能力 | 最低实现 | 验收条件 |
| --- | --- | --- |
| 创建记录 | 文字输入必须可用；手写画布优先实现 | 用户可创建并保存一页内容 |
| 原始内容保存 | 保存原稿和文本 | 刷新页面后记录仍存在 |
| OCR / 文本层 | 可编辑文本层；可是真实 OCR 或模拟识别 | 记录内容可被搜索 / 关联使用 |
| 记录库 | 浏览、搜索、按类型 / 时间 / 主题筛选 | 可找到并打开指定记录 |
| 单页阅读 | 查看原稿、文本层、主题、关联 | 原稿不会被 AI 摘要替代 |
| 主题 | 自动归类或手动修改；一条记录可多主题 | 用户能修改主题归属 |
| 关联 | 至少按文本、主题或时间生成关联 | 每条关联显示原因和来源 |
| 主动问答 | 输入问题、限定检索范围、返回答案 | 回答至少附 1 条可打开来源 |
| 待办候选 | 从内容生成任务和可选日期 | 不自动写入日历 |
| 时间册 | 展示月 / 日维度的任务 | 用户确认后任务出现在指定日期 |
| 响应式 | 手机、电脑均可完成核心流程 | 不依赖鼠标悬停；手机单手可操作 |

### T5 端与 Web 端分工

| 场景 | T5 设备端 | Web 端 |
| --- | --- | --- |
| 记录 | 开机即空白纸，手写 / 文字，自动保存 | 查看、编辑文本、补充整理 |
| 原稿 | 本地保留手写内容与缩略图 | 高清浏览、OCR 阅读、搜索 |
| AI 关联 | 仅显示轻量回响提示，不打断书写 | 展示关联依据、记忆线、知识问答 |
| 待办 / 日历 | 快速确认与查看当天 | 月视图管理、修改时间、筛选 |

## 6. 数据模型最低要求

```text
Note: id, title, createdAt, inputType, rawContent, rawText, topics[]
Topic: id, name, description
Relation: id, fromNoteId, toNoteId, reason, score
Task: id, noteId, title, dueDate?, status(candidate | confirmed | dismissed)
```

## 7. AI / 算法约束

- 可用 embedding、LLM、关键词、主题和时间距离组合生成关联。
- 必须提供无外部 API 时可运行的规则回退。
- 回答不确定或缺少材料时，明确说明"没有足够记录依据"。
- `Relation` 和问答结果必须返回 `sourceIds` 或等价来源信息。

## 8. 明确不做

- 会议录音硬件、NFC、投屏。
- 主动出题、自动复习计划。
- 全局复杂知识图谱。
- 没有来源的 AI 结论。
- 需要账户体系、付费或多人协作才能完成的复杂功能。

## 9. 设计授权（很重要）

Qoder 的设计 / 前端 Agent 可以从零决定：

- 信息架构、导航形态、页面命名；
- 色彩、字体、动效、插画、组件；
- 桌面和手机端各自的布局；
- 如何把"记录轻、过去回应"的概念转化为视觉语言。

它们不必保留当前仓库中任何 HTML 或 CSS，也不必使用"纸张""档案馆""记忆显影仪"等已有视觉概念。

唯一要求是：设计不能妨碍上述主流程、原稿优先、可溯源和响应式要求。

## 10. 演示脚本（约 90 秒）

1. 在 T5 / Web 记录页写下"想做一个减少通知打扰的设备"。
2. 保存后进入首页：展示与旧笔记《通知为什么会打断思考？》的回响。
3. 打开旧笔记，展示原稿、OCR 与关联原因。
4. 在知识问答问："我以前为什么认为低干扰输入重要？"
5. 展示带两条来源的答案，点击可跳回原稿。
6. 从本页确认"完成首页原型"待办，加入周五时间册。
7. 打开日历，显示任务已进入指定日期。
